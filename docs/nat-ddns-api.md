# NAT-DDNS 接口格式

客户端通过网站生成的 NAT-DDNS URL 获取 Sunshine 当前公网映射。

网站地址：

```text
http://stunddns.top
```

接口 URL 示例：

```text
http://stunddns.top/api/moonlight/<用户名>/<设备名>
```

## 返回格式

```json
{
  "host": "203.0.113.10",
  "tcp": {
    "47984": 52084,
    "47989": 52089,
    "47990": 52090,
    "48010": 53010
  },
  "udp": {
    "47998": 52998,
    "47999": 52999,
    "48000": 53000
  }
}
```

字段含义：

- `host`：Lucky STUN 打洞后得到的公网 IPv4 地址或可访问主机名。
- `tcp`：Sunshine 逻辑 TCP 端口到公网映射端口的映射表。
- `udp`：Sunshine 逻辑 UDP 端口到公网映射端口的映射表。

客户端会把 Moonlight/Sunshine 的固定逻辑端口替换成这里返回的公网端口。例如客户端需要连接 Sunshine 的 TCP `47989` 时，如果接口返回 `"47989": 52089`，实际会连接 `host:52089`。

## 必要端口

建议网站返回下面全部端口：

```text
TCP: 47984, 47989, 47990, 48010
UDP: 47998, 47999, 48000
```

当前客户端至少需要 `TCP 47989` 用于基础 HTTP 连接。Windows 客户端添加主机时还会检查 `TCP 47984`。实际串流需要 UDP 端口也能连通。

## 错误排查

- URL 打不开：先检查网站条目是否存在、域名是否可访问、Lucky 是否成功上报。
- `host` 为空：网站没有拿到有效公网映射。
- 缺少 TCP `47989`：客户端无法完成添加主机。
- 缺少 UDP `47998`、`47999`、`48000`：可能能配对和看到应用，但串流画面或控制会失败。
- 返回的是旧端口：在 Lucky 端重新打洞并让网站刷新，再在客户端刷新 NAT-DDNS 映射。
